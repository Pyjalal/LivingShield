## Architecture worth learning from

The rendering is a static browser application: Three.js **0.147.0** and legacy controls load from a CDN, followed by map data, sample content, the scene and UI scripts. The parent retains its newer React/Three.js stack; an isolated same-origin iframe vendors the matching Three.js 0.147.0 runtime for the adapted TamanKu engine. [Script loading](https://github.com/hongchenzhijin/TamanKu/blob/a78aa4d0f2caf558c473935c24e5b48ca11bdb4b/index.html#L109).

`tools/build_data.py` converts OSM nodes, ways and relations into a compact local-metre scene, with a fixed origin near 5.3915°N, 100.4095°E. It assembles polygon rings and holes, categorises roads/water/land uses, extrudes buildings and subdivides terrace rows into oriented boxes. Its generated dataset contains 318 road lines, 12 water lines, 59 areas, 118 building polygons, 473 terrace units and 23 named POIs. Of the terrace units, 445 derive from mapped rows and 28 are procedural infill; subdivision itself assumes house frontage. These counts describe a prototype representation, not surveyed individual dwellings. [Data generator](https://github.com/hongchenzhijin/TamanKu/blob/a78aa4d0f2caf558c473935c24e5b48ca11bdb4b/tools/build_data.py), [Generated data](https://github.com/hongchenzhijin/TamanKu/blob/a78aa4d0f2caf558c473935c24e5b48ca11bdb4b/js/map-data.js).

The scene uses perspective MapControls, polygon extrusion, instanced repeated meshes, batched road geometry, reusable materials, raycasting and projected labels. Layer markers draw attention to selectable locations. Day/night lighting provides atmosphere. Ground is a flat plane, and its road-graph routing is a prototype convenience rather than an emergency-access assessment. [Scene setup](https://github.com/hongchenzhijin/TamanKu/blob/a78aa4d0f2caf558c473935c24e5b48ca11bdb4b/js/world.js#L102), [Buildings](https://github.com/hongchenzhijin/TamanKu/blob/a78aa4d0f2caf558c473935c24e5b48ca11bdb4b/js/world.js#L342), [Instancing](https://github.com/hongchenzhijin/TamanKu/blob/a78aa4d0f2caf558c473935c24e5b48ca11bdb4b/js/world.js#L417), [Routing](https://github.com/hongchenzhijin/TamanKu/blob/a78aa4d0f2caf558c473935c24e5b48ca11bdb4b/js/world.js#L729), [Picking](https://github.com/hongchenzhijin/TamanKu/blob/a78aa4d0f2caf558c473935c24e5b48ca11bdb4b/js/world.js#L1214).

## HydroGrid Planet scope

The implemented **3D township resilience workspace** covers three 1.5 km pilot windows: Bandar Bukit Raja, Bandar Universiti Pagoh and City of Elmina. Existing national map/engineering tools continue to cover Peninsular Malaysia, Sabah, Sarawak and Labuan; those national tools do not imply nationwide 3D building coverage. Use recognisable OSM footprints, roads, mapped waterways and green areas; selection should connect directly to HydroGrid's source records, engineering inputs and reports.

Keep geometry auditable: retain OSM element type/ID, feature tags, source timestamp, geometry bounds and height provenance. Use explicit `height` values when valid, then tagged `building:levels` with a labelled storey-height assumption, then a clearly labelled display-height default. Preserve polygon holes. Do not invent missing buildings, parcels, drain dimensions, ground elevations or populations. A local metre projection suits neighbourhood scenes; recenter on each site rather than stretching one local plane across Malaysia.

Connect the scene to the existing sourced layers: JPS observations with timestamps; regional Malaysian drainage/pond records where published; JRC/Copernicus river-hazard cells with return period, approximate 90 m resolution and quality flags; MSMA/HP26 storm selection; and editable LID interventions. Show runoff volume, infiltration and peak-flow changes from HydroGrid's existing screening model beside intervention geometry. A before/after panel should state its calculation assumptions and source coverage.

JRC depth is water depth above local terrain, not an absolute water-surface elevation. Without a compatible terrain model, colour ground cells or show a labelled depth representation; do not flood an arbitrary flat plane and claim accurate building inundation. Likewise, changing a rain garden's screening parameters does not recompute a national hydraulic flood map. Synthetic rainfall animation can explain the selected design storm while sourced hazard remains a separate scenario.

Use instancing for repeated symbols, batch static lines, cap building counts, cancel old viewport requests and dispose GPU geometry on site changes. Add keyboard-accessible selection and a 2D fallback. The complete experience should keep source attribution visible and work when a regional inventory is unavailable.
